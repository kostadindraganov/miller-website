# Как се качва сайтът в Netlify (и как да остане бърз)

Ръководство стъпка по стъпка за всяко следващо качване на **miller-bg.com**.
Техническите подробности (env променливи, Google Sheet) са в [DEPLOY.md](./DEPLOY.md).

Сайтът в момента има **96–99 точки** за скорост на телефон в Lighthouse, а главната
снимка се показва за около **2 s** при бавен 4G. Целта е всяко качване да запазва
тези числа.

---

## 1. Как работи сайтът (накратко)

- Цялата страница, **заедно с менюто**, е готов HTML. Netlify го раздава от кеша си.
  Няма сървър, който да „мисли“ при всяко посещение.
- Менюто се чете от Google Sheet **най-много веднъж на минута**:
  - промяна в таблицата се вижда на сайта **до около минута**;
  - ако никой не е отварял сайта **10 минути**, първият посетител чака около половин
    секунда за свежо меню;
  - ако Google Sheets не отговаря, остава **последното добро меню**.
- **При всяко качване** Netlify чете таблицата, докато сглобява сайта.

---

## 2. Нормалното качване (всеки път)

```bash
# 1. Нов клон от най-новия main
git fetch origin
git switch -c моята-промяна origin/main

# 2. ...правиш промените...

# 3. Проверка на кода и build (виж секция 3)
npm run lint
npm run build

# 4. Commit и push
git add -A
git commit -m "Какво промених"
git push -u origin моята-промяна

# 5. Pull request към main
gh pr create --base main
```

6. Изчакай проверките на Netlify в PR-а да станат зелени ✅.
7. **Merge** на PR-а в `main`. Netlify качва сайта автоматично за 1–3 минути.
8. Направи проверките след качване (секция 5).

> Не качвай директно в `main` без PR. PR-ът пуска build в Netlify и хваща
> грешките, преди да стигнат до живия сайт.

---

## 3. Проверки ПРЕДИ качване

### 3.1 Build-ът трябва да показва, че страницата е статична

```bash
npm run build
```

В края трябва да видиш точно това:

```
Route (app)                Revalidate  Expire
┌ ○ /                              1m     10m
├ ○ /llms.txt                      1m     10m
```

| Какво виждаш | Какво значи |
|---|---|
| `○ /  1m  10m` | ✅ Всичко е наред: статична страница, обновява се всяка минута. |
| `◐ /` или `ƒ /` | ❌ **Страницата е станала динамична и ще е бавна.** Виж секция 4.1. |

### 3.2 Пробвай production версията локално

```bash
npm run build && npm run start
# отвори http://localhost:3000
```

Използвай `npm run start`, а **не** `npm run dev`. Dev режимът не кешира и е бавен,
така че не показва реалната скорост.

Локално, за да се вижда истинското меню, трябва файл `.env.local` с ключовете
(примерът е в `.env.example`).

### 3.3 Измери скоростта (по желание, но препоръчително при визуални промени)

```bash
npx lighthouse http://localhost:3000/ --only-categories=performance \
  --throttling-method=devtools --view
```

Целта е **95+ точки** и **LCP под 2,5 s**. Ако резултатът падне с повече от 5 точки
спрямо преди промяната, виж секция 4.

---

## 4. Правила за скорост (какво да НЕ чупим)

### 4.1 Страницата трябва да остане статична

**Не използвай** в страницата и компонентите ѝ:

- `cookies()`, `headers()`, `connection()`, `searchParams`;
- `new Date()` или `Date.now()` извън `getTodaysMenu()` в `src/lib/sheets.ts`;
- `fetch` към друг сървър извън `getTodaysMenu()`.

Всяко от тези прави страницата динамична: всяко посещение минава през сървър и
сайтът става около 0,5 s по-бавен. Нови данни от Google Sheet се добавят
**вътре** в `getTodaysMenu()`, която вече е кеширана.

### 4.2 Снимки

| Правило | Защо |
|---|---|
| Винаги `next/image` (`<Image>`), никога обикновен `<img>` | Netlify автоматично ги смалява и праща WebP. |
| Винаги задавай `sizes`, например `sizes="(max-width: 768px) 100vw, 50vw"` | Иначе телефонът тегли снимка за десктоп. |
| Само **главната снимка** (hero) има `fetchPriority="high"` | Ако всичко е с висок приоритет, нищо не е. |
| Всички други снимки остават `loading="lazy"` (това е по подразбиране) | Теглят се чак когато се стигне до тях. |
| Нови снимки: **WebP**, до около **1400 px** ширина, до около **150 KB** | Голям оригинал бави build-а и първото зареждане. |
| **Без** CSS `blur()` / `filter` върху големи снимки | Рисуването им е много бавно на телефон. |
| Фонови текстури (`background-image`): до 1200 px, до 30 KB | Не минават през оптимизацията на Netlify. |

Бързо смаляване на снимка (с `sharp`, който вече е в проекта):

```bash
node -e 'require("sharp")("вход.jpg").resize({width:1376}).webp({quality:80}).toFile("public/assets/img/изход.webp")'
```

### 4.3 Шрифтове (`src/lib/fonts.ts`)

- Предварително се тегли (`preload`) **само основният шрифт** (Neue Haas Unica).
  Всеки допълнителен предварително теглен шрифт (около 75 KB) бави главната снимка
  с около 0,4 s на телефон.
- Нов декоративен шрифт → винаги `preload: false` и `display: "swap"`.
- Махни шрифт, който вече не се ползва никъде. Заредените, но неизползвани шрифтове
  са чиста загуба.

### 4.4 JavaScript

- `"use client"` само когато наистина трябва интерактивност (бутон, копиране,
  скролване). Текст и снимки се показват без него.
- Преди да добавиш npm пакет за дребна функция, провери дали не може с няколко реда код.

### 4.5 Без лоудър на цял екран

Страницата пристига готова. Лоудър само би скрил готовото съдържание и Google
би я оценил като по-бавна. Ролята на лоудър вече я изпълнява размазаното превю
на главната снимка, което се показва веднага.

## 5. Проверки СЛЕД качване (2 минути)

```bash
# 1. Сайтът отговаря и се раздава от кеша на Netlify
curl -sI https://miller-bg.com/ | grep -iE "^HTTP|cache-status"
#    очаквано: HTTP/2 200  и  "Next.js"; hit  /  "Netlify Durable"; hit

# 2. Менюто е вътре в страницата (числото трябва да е броят категории днес)
curl -s https://miller-bg.com/ | grep -o '<article id="category' | wc -l

# 3. Менюто за AI асистенти
curl -s https://miller-bg.com/llms.txt | head -20

# 4. Ботовете са допуснати (всички трябва да дадат 200)
for ua in Googlebot GPTBot ClaudeBot PerplexityBot facebookexternalhit; do
  printf "%s -> " $ua; curl -s -o /dev/null -w "%{http_code}\n" -A "$ua" https://miller-bg.com/
done

# 5. Скорост на живия сайт
npx lighthouse https://miller-bg.com/ --only-categories=performance --view
```

Ако си сменял снимката или текста за споделяне, отвори и
[Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/),
въведи `https://miller-bg.com` и натисни **Scrape Again**.

## 6. Настройки в Netlify (веднъж, но е добре да се провери)

| Къде | Какво трябва да е |
|---|---|
| Site configuration → Environment variables | `GOOGLE_API_KEY`, `SPREAD_SHEET_ID` (и по желание `SHEETS_REFERER`) с обхват **Builds** и **Functions** |
| Build & deploy → Build settings | Взима се от `netlify.toml`: `npm run build`, publish `.next`, Node 22 |
| Build & deploy → Branches | Production branch: `main` |
| Access & security → Visitor access | **Production без парола** (иначе Google и социалните мрежи получават 401). За Deploy Previews паролата е по избор, но без нея можем да тестваме скоростта преди merge. |

## 7. Когато нещо се обърка

| Проблем | Причина и решение |
|---|---|
| **Build-ът в Netlify спира** с грешка от Google Sheets (`batchGet -> HTTP 403/400`) | Таблицата не е споделена като *Anyone with the link → Viewer*, ключът е сгрешен, или env променливите нямат обхват **Builds**. Живият сайт остава на старата версия, нищо не е счупено. Оправи и пусни **Retry deploy**. |
| Сайтът показва „Менюто за днес очаквайте съвсем скоро“ | Липсват env променливи или всички табове в таблицата са празни. Провери в Netlify → Logs → Functions. |
| Промяна в таблицата не се вижда | Изчакай до минута и презареди страницата. Ако след 2–3 минути още не се вижда, провери дали името на таба е точно като в `CATEGORIES` в `src/lib/sheets.ts`. |
| Сайтът изведнъж е бавен | Пусни `npm run build`. Ако `/` вече не е `○`, виж секция 4.1. После провери снимките и шрифтовете (4.2, 4.3). |
| Нужно е **бързо връщане назад** | Netlify → **Deploys** → избери последния добър deploy → **Publish deploy**. Става за секунди и не изисква код. |
| Сайтът връща **401** | Някой е включил парола в Visitor access. Махни я за production. |

## 8. Добавяне на нова категория в менюто

1. В Google Sheet добави нов таб, например `Закуски`, с колони
   **ИМЕ | ГРАМАЖ (или Брой) | ЦЕНА** и заглавен ред на ред 1.
2. Добави снимка в `public/assets/img/` (WebP, около 1376×768, до около 150 KB; виж 4.2).
3. В `src/lib/sheets.ts` добави ред в `CATEGORIES`:
   ```ts
   { title: "Закуски", picture: "breakfast-board.webp" },
   ```
   `title` трябва да съвпада **буква по буква** с името на таба.
4. Качи по стъпките от секция 2.

Структурираните данни за Google, `/llms.txt` и навигацията с категориите се
обновяват сами.
